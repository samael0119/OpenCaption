# OpenCaption 开发计划

2026-09-07；对应 PRD v1.0 修订 2。本文描述目标；已执行结果另见实施记录，不能以计划代替验收。

## 目标与边界

小米 15、前台麦克风、英语到简中、稳定字幕和会话回看。一个 Flutter App，无独立后端；Kotlin 管音频与调度，whisper.cpp／llama.cpp 管推理，不引入 Rust。模型首次下载后离线运行。外部增强只翻译文本，用户主动提供地址、模型、可选 Key；不上传音频、不自动切换。

P0 包含本地识别、离线翻译、模型管理、CS 词表、会话状态、错误与诊断、可选 BYOK。保存导出、iOS、扩展领域包在 P1；斗鱼同机采集、悬浮窗、后台收音在 P2。

本地翻译候选按可用质量优先。当前以 Qwen2.5 0.5B Q4_K_M 与 Qwen3.5 0.8B Q4_0 做轻量对照；NLLB-200 distilled 600M 等待 llama.cpp encoder-decoder 支持或独立运行时接入。候选必须比较首句准备耗时、稳态字符／token 吞吐、关键含义错误和主观可读性。

## 接口与实现

- Dart 统一 Session 状态和字幕；Session 带 ID／运行代次／模式／版本；Segment 带稳定 ID／序号／时间范围／修订／原文／译文／状态。过期回调不进入字幕。
- Pigeon 定义控制和结果事件；AudioEngine 负责采集和原生停止保护；AsrEngine 负责窗口识别；TranslationEngine 负责当前句翻译；ModelManager 负责下载／导入／校验／删除。PCM 留在原生层。
- 16 kHz 单声道，必要时真实重采样；Silero VAD；停顿 600 ms；首次识别 2 秒；刷新 1.5 秒；4 秒起寻找完整短句；边界重叠 0.5 秒。参数是实验起点。
- 按一致前缀、完整词和分句边界稳定提交；重叠按时间和文本对齐；真实重复词保留。仅稳定英文进入翻译，中文确认后不改写。没有安全提交点继续等并报告失败。
- 重任务先串行、CPU 2／4／8 线程对照；收音／VAD 独立。RMS 兼容路径按约 600 ms 静音或最多 7 秒连续语音提交最终识别，保证音频在 10 秒环形缓冲覆盖前进入推理；恢复可靠的 Silero 路径后再评估临时结果。
- 翻译 10 秒超时包含排队；按序提交，不允许后句倒序显示。暂停／结束 1 秒停止输入，最多 3 秒收尾，再拒绝过期结果并协作取消；任务退出前不释放引擎。
- Qwen 关闭思考，4096 token 窗口，最多 5 句／800 英文词，超限移除最旧历史。ML Kit 不伪装术语／上下文接口。暂停及长中断清空上下文。
- 模型由随版本固定清单控制，包含大小、SHA-256、格式、固定提交与多个来源。Whisper、Qwen 和 Silero 预置魔搭国内源、HF Mirror、Hugging Face；下载前并行请求 64 KiB 范围测速，按耗时选源，失败时保留断点切换，最终只按清单大小与 SHA-256 校验后原子启用。手动导入仅限受支持模型。ML Kit 使用 SDK 管理，无法替换下载源。正式列表仅包含验收通过组合。
- 外部接口仅 model/messages/stream:false；固定句连接测试；Key 使用系统安全存储；HTTPS 默认，局域网 HTTP 显式开关。错误不自动切服务；只记录文本用量，缺少单价显示费用未知。
- 原始音频不持久化，字幕仅会话内；偏好、模型和连接配置持久化。测试录音与文本诊断需显式开启并与默认无内容诊断隔离。

## 验证与发布

先人工参考英文评翻译，再接识别，最后小米外放实录。30 段约 45 分钟、至少 10 位说话人；20 段开发、10 段保留；另 5 分钟静音／音乐／观众声。按场次说话人拆分，不能以保留集调参后继续宣称独立验收。

单元测试覆盖生命周期、旧代次、乱序、重复、超时、分段、队列和上下文；协议测试覆盖空回复、非法数据、401/403、429、5xx、断网和预算；原生测试覆盖缓冲、时间戳、取消与共存；管理测试覆盖最快源选择、Range 元数据、跨源断点续传、全部源失败、损坏、错误模型、空间不足及使用中删除。

发布要求：理解／术语／名称各≥90%；关键否定／数字错误为0；中文延迟P50≤3s/P95≤6s；90%长句首条≤8s；热准备P95≤3s/冷≤8s；重复乱序为0；3×60分钟无崩溃ANR或持续积压；静音音乐零虚构字幕。成功覆盖率、超时和丢句必须同时报告。

内存1.5GB为初始目标，离线耗电初始预算≤20个百分点/小时；超预算单列评审，不降低质量门槛。固定亮度50%、室温、不充电并登记设备。外部增强单独测150ms额外RTT、1%丢包、10秒断连。离线在模型齐全后飞行模式验收。

PRD 修订2同步默认模式、P0/P1、模型能力、费用、异常、内存和阶段；保留斗鱼P2边界。SDK能力、初始参数、实际成绩必须区分。每次默认模型或预算变更均同步修订记录。实机验收前仅提供开发评测包。
