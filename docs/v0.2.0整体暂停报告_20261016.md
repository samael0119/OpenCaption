# OpenCaption v0.2.0 整体暂停报告

2026-10-16。按用户明确暂停指令汇总既有证据；本次只读取、校验和保存报告，没有启动模型、测试、构建或迭代。opencaption 的实际配置已核验为 PAUSED，未发现本任务推理进程。

## 结论与完成距离

当前是“已有四项主要功能的开发候选，关键效果仍未验收”，不适合称 v0.2.0 完成版。不是只剩打包或两小时长稳；核心准确性路线还没有找到能同时满足收益与覆盖护栏的候选。

不能给可信的整版完成百分比：代码存在、单测通过、实验轮数与用户可见收益并不等价。可量化的进度是：四个主要方向已有实现；10个完整优化轮已结算，第11轮仅完成准备和诊断；持续优化主账累计639次模型请求（不包含此前S0、资源长稳等另账实验，不能称项目全部调用量）；独立确认的整体净收益仍0项。以下五类关键验收仍未闭合：内容质量、稳定中文延迟、术语净收益、现实场景确认、最终联合交付。五项不是等权任务，不可把数量换成百分比。

开发预览的相对改进门槛与正式发布的绝对目标分列：预览仍须证明延迟/覆盖和术语/场景收益；正式目标包含理解/术语/名称各至少90%、稳定中文P50不超过3秒/P95不超过6秒等。当前连前者也没有全部通过。

## 延迟：已知速度与未测项

| 指标 | 当前证据 | 与目标的关系 |
|---|---|---|
| 本机模型解码 | 旧首份联合1009请求：P50 1.939秒，P95 3.329秒 | 解码组件时间，不能判定屏幕目标通过 |
| 本机排队 | 同批P50约0.002秒，P95 2.034秒 | 不得与解码P95相加得到端到端P95 |
| 最初停顿收益 | 同120秒开发片段，4次双方有效返回中位提前2.059秒；另1次提前提交无效 | 小样本调度代理，未证明独立稳定中文P50改善20% |
| 稳定正确中文显示 | 人工语义结束→实际稳定中文绘制：未测齐 | 预览相对P50改善≥20%/P95回退≤5%未验收；正式P50≤3秒/P95≤6秒差距未知 |
| 后续400ms候选 | 29个SRT单元提交等待代理P50 1994→2619ms | 变慢625ms，否决；没有改600ms默认 |
| 后续锚定5秒候选 | 默认起点P50 1994→2815ms，四种起点不稳，短片段1→5 | 负载/覆盖护栏也失败，否决 |
| 流式完整中文上界 | 6个有声样本完整最终中文提前中位0.500ms，最高41.51ms | 远低于20%且200ms筛选门槛；首段预览提前约473ms不能算稳定整句收益 |

结论：初版停顿机制有局部依据；后续继续压停顿阈值、改变硬期限或提前展示流式内容，没有证明能改善稳定完整字幕。尚不能回答“现在用户看到字幕平均快多少秒”。

## 准确性、术语、场景与音乐

不同材料和评分单位不合并为一个“当前准确率”。AI辅助句子评分均属开发诊断，不是独立人工验收。

| 指标/材料 | 数字 | 距离与限制 |
|---|---|---|
| 已集成短输入：48例/48位新说话人单词，原词+译词严格联合 | 37/48→39/48，77.08%→81.25%，+4.17个百分点 | 局部正向；仅拿90%作本组参考，需至少44/48，即再正确5例。不能外推整句/赛事质量 |
| 真实耳语旧18例，严格原文匹配 | 基础CS2提示7/18=38.89%；无提示8/18 | 仅1位说话人，明显困难，不能当整体准确率 |
| 最新新材料：主6条音频完整中文 | 4/6=66.67%，原子语义13/16=81.25% | 新开发基线，没有候选对照；6条上达到90%需6/6，样本太小不能据此推算现实差距 |
| 同6条人工英文文本控制 | 6/6完整中文、16/16语义项 | 输入已经正确且任务不同；只是诊断上界，不能称产品从4/6提升到6/6 |
| 最新损失归因 | 3项中文损失在英文也存在，来自2条录音 | 支持关注上游识别/指代，但没有定位可修算子，未达到3条不同新录音共同机制的候选前置条件 |
| 独立真实CS2术语错误净减少 | 未测/未证明 | 目标至少减少20%，净修复至少3例、基线相关错误至少10个；没有可报告的达标差值 |
| 旧Nuke片段真实闭环 | 地图8/10窗口确认；双队0/10（两缓存变体合计0/20窗口） | 同一旧来源，窗口覆盖不等于精确率；不能用80%窗口覆盖去减95%精确率 |
| 合成充分证据场景 | 地图6/6、双队4/4；明确冲突1片段解除 | 下游机制有限通过，不是现实地图/队伍精确率各95%、充分证据后30秒正确覆盖80%的验收 |
| 联合音乐旧审核 | 同一钢琴来源82个合格窗口中2次可见虚构 | 零虚构门槛失败；2/82不是独立音乐总体误报率 |

最新全8条新录音格式交付8/8。另2条单列：1908有语境歧义；1978发布方中译将“结束五连败”写为“以五连败收官”，且模型队名也有问题。原参考、难例和未知判断全部保留，没有删例或改金标提高成绩。

确定保留的工程收益：纯NONE协议1156条旧输出回放中修复1条invalid→NoSpeech、940条字幕保持；非事实否定场景14个机制例错误11→0，60项场景回归通过。这些不能换算为中文内容准确率提高。

## 工程稳定性与剩余工作

- 历史完整开发回归Dart129项、Kotlin39项；之后另有协议19项、场景60项等专项，存在重叠，不能相加成新的完整全套总数。当前APK已构建并签名，本次只核验93源和APK哈希。
- 模型资源子实验3×60分钟完成；真实产品核心/widget联合仅1/3完整，首份3600.013秒/1009请求，队列缺口0、invalid0、峰值3.864GiB、观察swap0/OOM0。
- 用户中止的run2为757秒/202结果，不计完整60分钟，不能续接凑数。若旧run1对最终改动仍适用，最低还需两份完整60分钟真实联合输入；若关键链路改变，须明确重新验证范围。这不是“再两小时就能完成”。
- UI已有本机浅/深色、390窄屏和大字等证据；没有整体视觉分数或真实稳定字幕绘制时延。Android实机性能全部未测，按约定不连接手机，也不将其作为这轮本机任务阻塞项。

真正剩余的是五个验收闭环：①可靠参考与内容候选，②逐句稳定中文显示计时与分段配对，③真实术语净收益，④多赛事地图/队伍确认与恢复，⑤最终版本联合/UI/构建和缺少的长稳。前四项有研发和数据风险，不是执行既定脚本即可完成。独立确认尚未开始，不能承诺再几轮或多少token一定结束；实际开发token usage未知。
