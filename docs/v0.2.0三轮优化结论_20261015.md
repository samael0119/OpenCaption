## 延迟究竟改善多少

目前**没有**人工语义结束→本机真实绘制稳定中文的合格端到端配对结果，所以P50改善≥20%、绝对P50≤3秒/P95≤6秒及P95回退≤5%都未验收。

- 旧停顿开发片段：英文WER32.43%→29.24%；仅4次有效提前返回，中位提前2.059秒。这是调度/解码返回代理，不能当全部字幕快2秒。
- 旧核心/widget首份60分钟：1009请求，解码P50/P95=1.939/3.329秒，排队P95=2.034秒；两个P95不能相加。run1属于旧配置证据，不是当前新修复的完整联合稳定证明。
- 第3轮本机解码中位：耳语1.389→1.402秒（慢0.92%）、普通声2.468→2.460秒（快0.32%）；没有明显稳定收益。这不是屏幕延迟，也不是正式端到端P95。
- 第3轮3次模型初始化单列3.315/4.193/3.337秒；加载后首调用单独标记，FLEURS剔冷后两臂样本不等不作同例提速证明。模型默认None内部实际MTP状态仍不可观测，不把它说成强制开启。

第3轮单模型串行3次加载、同锁、6GiB/swap0/600秒退出0；cgroup峰值3901390848字节约3.633GiB，OOM/OOMKill0。模型均关闭、scope inactive/dead、无本任务在途推理或联合进程。推理期间未构建。

## 判断与停止原因

停顿提前提交、队列约束和保守场景治理有保留价值；三轮证据不支持继续把音量/降噪/提示拆分或本次解码开关微调当主要准确性路线。已观察英文信息丢失使术语/场景下游无法恢复事实，但这只定位有限开发数据的瓶颈，未证明模型的普遍能力上限。后续重启应提出实质不同、可检验的识别/输出机制并配新的独立确认来源；不能直接把未胜出的ASR或大模型替换说成已验证方案。

本次依据连续3完整轮净收益未证实停止，保留两项确定工程修复与全部失败。没有为跑满三份长稳延后质量判断，也没有无限追加同轮小包。自动化已PAUSED，任务进程已退出。一次免费重置卡跨轮累计**尝试0、使用0**，最后大包启动前5小时剩余84%、周10%，未触发双窗均严格小于5%的条件；未购买、兑换或重建授权账本。
