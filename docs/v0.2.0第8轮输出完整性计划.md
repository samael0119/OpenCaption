## 已确认的机制依据

当前 E2eProtocol.parse 使用 pair.findAll(cleaned).lastOrNull()，因此有多组标签时选最后一组；不是整段匹配。CaptionEngine.inferEndToEnd 对该结果直接发一个 bilingual 事件。这个实现事实允许两种相反解释：前面可能是应保留的连续字幕，也可能是模型纠正前次答案。不能直接把多个匹配拼接，也不能将所有多组输出一概拒绝。图索引元数据过期，已回退读取当前源码确认上述行为。还没有确认1156旧输出中实际发生多少次，不能宣称存在真实净损失。

只有P0发现真实原输出可重现的缺陷，且能用确定性规则区分正反例，才实现一个最小候选。优先修复已经明确无效的混合内容被当作有效字幕、或已有完整配对在确定性清理中丢失；不得用语义猜测合并不同答案。对于多组不同字幕，若无法区分连续话语与纠正，不修改选择策略并明确上界。最多一个候选；机制改变需回astra，不追加同类宽松正则。
