# 第10轮：PCM16往返保真与产品输入一致性

2026-10-16 astra/medium审定。当前主计数599、周剩62%/5h95%，ACTIVE。先证实确定性数据损失，再评估模型效果；工程位保真不冒充中文准确率增益。

## 已核实的真实机制

CaptionEngine.capture读取PCM16后用pcm/32768f；GemmaBackend.wav用float*32767并toInt截断。两者复合不是整数恒等，最小非零值存在被归零的可能。这是明确的编解码比例不对称，与此前对原始音频盲目增益/FFT/精度调参不同：候选目标恢复采集值，不人为放大原录音或按能量拒绝。

产品对E2B不足32000点的非零输入先prepareShort前置零；旧PythonAudioFile基线直接送文件。本机旧41例中1272-135031-0009仅30560点，漏了产品1440点前补；其旧输出为He doesn't work at all/他根本不工作。其余40条已>=32000（已知短音乐已经补齐）。旧基线不能直接冒充当前产品输入，原报告保留并追加适用性说明，不抹掉旧失败或把此前整体无收益都归因于这一差异。

图查E2eAudioInput未跟踪、CaptionEngine/FlavorBackendFactory元数据过时，已读当前源核实。需记录当前源码SHA及精确片段，非猜测bug。

## P0零模型：穷举与输入冻结

1. 当前真实E2eAudioInput重新编译。独立JVM实验桥接按当前capture浮点规则与wav方法原样提取/复现，注明提取源范围及SHA，不伪称已编译完整Android类。当前路径先prepareShort再编码，候选只把编码标度恢复为32768并饱和到[-32768,32767]，明确Float运算/截断与边界处理；不修改采集时间戳、切点、VAD、队列或模型。
2. 穷举65536个PCM16值，记录当前和候选的逐样本错误数、最大误差、非零→零个数；候选必须65536/65536位相等。至少正负极值/±1/0、空/全零/短弱声/2秒边界/长输入等最多12项序列测试。浮点NaN/无穷及范围外行为需与旧实现明确对照，不能借修PCM改变未知输入策略。
3. 用同一新JVM桥接生成41例current_product与lossless_candidate WAV，逐例记录原输入SHA、长度/前补、量化变化数、RMS前后、候选非补零部分是否与原PCM完全一致。基线必须包含既有前补，不能把前补差异混入候选效应；只补一次，所有原非零样本保留、无trim/gain/重采样。旧缓存只作明确的相同输入/提示质量回放，不作本轮配对耗时。
4. 先只改评测桥接，不改产品默认。若源链与预期不符，或不能精确还原现有处理，保存证据修工程，不启动模型。P0不算完整轮/中文收益。
