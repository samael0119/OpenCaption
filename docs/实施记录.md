# 实施记录

更新：2026-09-07。本文件记录代码和验证状态；开发计划仍是目标，尚未完成发布验收。

## 已落地

- Flutter Android 应用骨架，首页、字幕会话、暂停 / 恢复 / 结束和回看、字体 / 主题 / 英文显示、模型管理、外部服务设置。
- Pigeon Dart / Kotlin 桥接，前台 16 kHz 单声道 AudioRecord、Silero VAD、固定容量音频环形缓冲、串行推理队列、whisper.cpp / llama.cpp JNI、ML Kit 翻译。
- small.en Q5_1 默认候选、base.en Q5_1 对照、Qwen2.5-0.5B Q4_K_M 与 Qwen3.5-0.8B Q4_0 翻译候选；NLLB-200 distilled 600M 因当前 llama.cpp 不支持 encoder-decoder 而暂时禁用。模型清单固定大小与 SHA-256，下载 / 导入校验、临时文件启用、启动前复核。ML Kit 通过官方 SDK 管理。
- Whisper、Qwen 与 Silero 已预置固定提交的魔搭国内源、HF Mirror、Hugging Face。下载前并行 Range 测速，自动选择最快可用源；源失败后保留断点切换，最终仍以固定大小和 SHA-256 为启用条件。界面显示测速、当前来源、切换和校验阶段。ML Kit 下载源由 Google SDK 控制，国内网络建议优先使用 Qwen。
- 点击开始时在 Android 公共 Downloads 创建时间命名的诊断日志，逐行刷新模型文件大小、Java 堆、Whisper／VAD／Qwen 原生加载阶段、AudioRecord 初始化和捕获异常；不记录音频、字幕、Key 或完整模型路径。该日志用于无 ADB 环境下定位进程死亡阶段，不能替代 native tombstone 的完整调用栈。
- 小米 15／Android 16 日志显示模型与 AudioRecord 均成功后，进程在首个 Silero streaming VAD 帧被 native 信号终止。当前评测包临时使用普通 MIC 与 Kotlin RMS 能量门（初始阈值 0.0015）绕开该调用，保留 Whisper 与翻译链路；Silero 模型仍加载但不参与逐帧判断。日志每秒记录峰值供实机校准。该兼容路径需要实录重新校准，不能视为 Silero 质量验收通过。
- 后续真机日志显示 27,456 个采样的 base.en 推理在 debug 原生 `-O0` 下超过 50 秒仍未完成。Android debug 包现仅保留 Flutter/JNI 诊断能力，GGML、Whisper 与 llama 统一以 `-O2 -g0` 编译，使评测包性能接近 release；真实性能仍以日志中的 `asr_ms` 和专项评测为准。
- 字幕页新增实时模型运行卡片，显示最近识别延迟、RTF、识别／翻译输出字符每秒和翻译延迟；结束页保留本次运行时长、调用次数、平均／最大延迟及丢段汇总。当前接口不把字符吞吐冒充 token/s，Qwen 真实 TPS 待 llama.cpp 返回生成 token 数后补充。开发机具备额外可用内存后，Gradle 与原生编译上限调整为 8 worker，链接仍串行。
- 实机连续赛事解说暴露 RMS 门持续判为讲话、10 秒环形缓冲覆盖旧音频的问题。能量分段现在遇到约 600 ms 静音正常收句，连续讲话则最多 7 秒强制形成最终识别；强制分段之间不重复音频，也不再对不断增长的同一句每 1.5 秒重复推理。首页直接显示并选择本次使用的识别模型，模型管理卡同步标记当前模型；每次只加载所选模型。推理线程支持 2／4／8，默认仍为 4。
- 将用户提供的 `cs2_zh_broadcast_corpus_v0.1.json` 转为版本化内置语料包：去除 1 条重复记录后包含 113 条唯一术语。`assets/corpora/manifest.json` 可登记同一领域的多份包，加载时按英文主词合并去重。匹配同时检查主词和别名，并限制每句送入翻译的相关条目数量；优先级 5 的词条与当场名称组成有长度上限的 Whisper 初始提示。首页显示已启用语料包与术语数。原文件引用的网页未声明可再分发许可证，内部包保留来源和 `license_status`，发布前仍需完成来源许可复核。
- 首页与字幕页新增“当前运行组合”，明确显示英文识别模型、实际 RMS 分段、英译中实现、CPU 线程和语料包。翻译选项改为明确的 ML Kit 端侧无上下文、Qwen3 本地术语／上下文及外部兼容 API；选择会持久化。模型管理页同步标记当前识别和翻译模型。Silero 因实机兼容问题不再作为启动必需项，也不再在 RMS 路径中加载。
- ASR 和翻译拆为独立工作队列，模型加载／释放使用读写锁，允许 Whisper 与已加载翻译引擎安全并行；翻译积压不再阻塞收音识别。Qwen 上下文缩减为最近 3 句、最多约 160 个英文词，每句最多注入 6 个相关术语；生成改为确定性贪心、最多 160 token。ML Kit 超时 10 秒，Qwen 超时 30 秒，后续已完成译文无需等待前一条。失败译文在收音空闲时自动重试一次，结束回看支持单条或全部手动重试；返回首页时才释放正常结束会话的模型。
- 稳定英文提交、确认后不改写、按序显示译文、超时退回英文、过期代次和重复回调保护。暂停清空翻译上下文；前后台、麦克风打断、严重温升和内存压力处理。
- 外部非流式 Chat Completions 文本协议、HTTPS / 显式私网 HTTP、Key 安全存储、连接测试、用量缺失提示、软 token 预算、请求取消。音频留在原生内存。
- 同步 PRD 与开发计划，补充启动说明、评测要求。模型与引擎源码不纳入 Git；引擎提交固定，桥接生成代码及依赖锁文件随项目管理。

## 尚未验证或未完成

- M0-B 质量 / 延迟选型、独立保留集、飞行模式、3×60 分钟、温升 / 电量 / 内存及正式签名发布均未完成。所有模型在清单中标为未通过发布验收。
- 目前要求设备支持 Android 的 16 kHz 录音输出；不支持时报告格式错误，尚无自定义重采样回退。

- Qwen 提示超过 token 上限时失败并保留英文，尚未按 tokenizer 动态逐项缩减历史。ML Kit 无术语 / 历史提示接口，也不支持取消已经进入 SDK 的单次翻译；过期结果会被忽略，释放等待任务退出。
- 外部 429 / 5xx 显示失败并保留英文，尚未做 Retry-After 有界重试；软预算基于服务返回用量，不等于费用硬上限。
- 模型损坏、断点下载、空间不足、使用中删除等完整管理回归，以及原生推理取消、双引擎共存实测仍待补齐。

## 2026-09-13 正式版稳定性与任务模式轮

- 排查发现 Flutter release 默认启用 R8；LiteRT-LM 依赖的反射／原生绑定在裁剪或改名后可能导致 Gemma 正式版启动或推理闪退。Gemma release 暂停代码与资源缩减，待补齐并实测 keep 规则后再恢复，以稳定性优先。
- Gemma 端到端任务新增“仅中文转写”，只请求简体中文转写，不进入翻译队列；英文转写、双语和自动识别任务继续共用同一模型。
- Gemma 不加载 Silero，也不运行级联 RMS 语音门；连续窗口直接交给端到端模型，RMS 仅用于音量活动条，级联路径才使用停顿分段。
- 字幕页状态栏改为始终可展开的一行摘要，显示阶段、最近推理耗时、待处理窗口；端到端运行还显示模型运行内存和温度状态。测试版展开后可查看完整计时与过滤计数，避免把不存在的指标显示为 0。
- 后台本设备音频提示明确：系统弹窗虽称录屏／投屏授权，应用只采集音频；允许共享的直播 App 在佩戴耳机时也可使用，麦克风模式仍只能收取外放或环境声音。

## 2026-09-14 LiteRT-LM 主线与文档同步轮

- LiteRT-LM Android 与本机评测统一到 `0.17.0`。Gemma E2B 与 E4B 均使用 LiteRT Community `.litertlm` 包；Android 端优先 GPU，失败后使用 CPU 回退，音频编码和 CPU 回退遵循同一组 2／4／6／8 线程设置，默认 4。
- Gemma Android 接入 MTP／speculative decoding，`maxNumTokens=768`、最大输出 128 token、关闭 thinking，使用应用磁盘 cache；本机评测支持 MTP 开关、`memory`／磁盘 cache、warmup 和 systemd cgroup 实际内存限制。应用实时路径不插入 dummy warmup。
- 模型目录加入 Gemma E4B，并为各模型加入用途文案；Gemma E2B 标记为默认和优先推荐，E4B 标记为质量优先。默认主题改为跟随系统，主题切换立即刷新并持久化。
- 同一份音频和金标在 6 GiB cgroup、memory cache、warmup、MTP＋768 口径下：E2B 平均窗口推理约 2.862 秒、WER 29.90%；E4B 约 5.311 秒、WER 22.36%。手机实测范围为 E2B 约 0.6～1.6 秒、E4B 约 2.6～6 秒；该数据仍非跨设备验收结论。
- Qwen3.5-0.8B 在真实 cgroup 内存限制下仍无法稳定完成金标回放；TranslateGemma-4B-IT 当前只有 MediaPipe Web `.task`，LiteRT-LM 不能加载。两条路线暂不作为下一步方向；旧 cascade／Qwen flavor 仅保留兼容和历史对照。
- README 与当前 PRD 已改为区分主线实现、旧兼容路径、实验结果和发布门槛；当前仍不宣称模型质量、长稳、功耗或多设备兼容已验收。
