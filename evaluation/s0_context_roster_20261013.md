# S0 补充验证：分段、context 与转会词库

日期：2026-10-13。接续 [首轮 S0](s0_feasibility_20261013.md)。本轮新增 50 次配对推理、2 次离线 warmup，仍为单模型串行、6 GiB cgroup 上限、禁用 swap。当前未连接 Android，结果不能外推手机 GPU 或 UI 延迟。

## 1. 先澄清分段含义

首轮有两类不同测试：1/2/3/4/5 秒固定前缀用于测服务时间；完整音频的停顿对照按 Silero 语音概率寻找语音结束，累计约 600 ms 非语音才提前提交。若一直讲话或 VAD 无法确信停顿，则在 5 秒硬上限提交。

因此目标是“**声音空隙优先＋最大时长兜底**”，不是持续按固定短窗截断，也不能等待一句话完全说完才提交。比赛背景观众声可能让低能量空隙不明显，VAD 判断的是语音而非精确无声；硬上限仍不可少。原型的 20 ms 采集调度只使用已经完成的 32 ms VAD 帧，保留全部音频，没有未来信息或全局静音裁剪。

## 2. 768/1024 的配对对照

模型、CPU 线程、MTP、输出 128 token、5 秒音频、采样参数和 system 指令相同。每个上限分别驻留一份 E2B；3 个相同音频区间、4 种提示布局、每种 2 次重复，另有 1 个长提示压力样本。第二遍反转布局顺序减小顺序偏差，但两种 context 仍分批执行，不能完全排除机器负载漂移。

| 布局 | 768 双语协议 | 1024 双语协议 | 768 推理中位数 | 1024 推理中位数 |
| --- | ---: | ---: | ---: | ---: |
| 无额外提示 | 6/6 | 6/6 | 3.233 秒 | 3.392 秒 |
| 简短 ID/别名提示 | 4/6 | 4/6 | 2.967 秒 | 3.181 秒 |
| 已知比赛场景＋术语映射 | 0/6 | 0/6 | 2.663 秒 | 2.738 秒 |
| 最近两条模型原文 | 2/6 | 2/6 | 2.458 秒 | 2.563 秒 |

前三个普通区间分别为原 clip 的 10～15 秒、25～30 秒和 Nuke clip 的 10～15 秒。场景输入来自素材说明，是已知信息对照，不能当作自动识别成果。

普通 24 对请求在两个容量上限下的原始输出全部相同。无额外提示组 1024 比 768 中位数高约 **4.9%**；全程峰值 RSS 从约 **2.041 GiB** 到 **2.090 GiB**，增加约 50 MiB。本轮样本少，协议失败的布局因为输出更少可能更快，不能把其耗时较短说成性能优化。没有中文语义的独立评分，不宣称总体准确性相同。

长提示压力样本的 system/任务粗略文本 token 为 598：

| 指标 | 768 | 1024 |
| --- | --- | --- |
| 会话 token 计数 | 768，触达容量 | 779，未触达容量 |
| 中文输出 | 停在“我知道钳子来了。他们” | 返回完整中文句子 |
| 推理耗时 | 2.703 秒 | 3.533 秒 |

768 的这个回复仍满足双语解析结构，却丢了后半句；**协议通过不能代替内容完整性**。1024 的新增约 0.83 秒同时包含更大容量和更多输出的成本，不能全归因于扩大上限。即使返回完整句子，仍存在声学/语义错误，扩大容量并没有修正它们。

两个概念需要分开：

- **容量上限**决定能容纳多少上下文，也可能改变分配与运行开销。上限变大，不意味着每次请求自动多带知识。
- **实际输入长度**取决于音频、前文、词条与模板；增加实际内容会增加处理工作，也可能干扰模型。短场景提示本轮在容量充足时仍只输出中文，属于提示行为问题。

### 平衡建议

以 768＋紧凑检索作为当前基线，先让提示保住双语覆盖，再证明术语净收益。真正需要更多有效前文时，1024 是合理候选，但应验证手机质量、稳态延迟和内存，不直接给所有场景加长。

只保留相关实体、地图条件和短前文，优先移除低相关词条；同时记录会话计数、输出长度与限长疑似事件。接近容量的结构完整回复也需要审计截断，而不能只依赖两行解析。

`maxNumTokens` 属于引擎配置。P0 在会话准备时确定容量，单句内调整实际提示预算；不要为了个别句子不断重建引擎切换容量，重新装载的等待可能抵消收益。

## 3. 转会词库：身份稳定，归属有时效

增加了 [身份/关系评估原型](s0_context_roster.py)，并非完整的生产场景识别器：

| 输入/问题 | 原词库检索 | 改进原型 |
| --- | --- | --- |
| `Shiro` | 可检索到 sh1ro，但模型输出常保留 Shiro | 唯一已审核别名规范化为 `sh1ro`，不增加模型调用 |
| `a little bit` | `bit` 别名会支持 NAVI 候选 | 将普通词别名标为弱证据，不改写为 b1t |
| `wonderful / frozen` | 普通词和选手 ID 可混用 | 保留候选，不凭单次词面建立强场景关系 |
| karrigan、日期未知 | 当前快照指向 Falcons | 仅作为 2026-09-09 快照候选，不作为永恒归属 |
| karrigan、模拟历史日期早于快照 | 当前快照仍可能导出 Falcons | 返回历史归属未知，不拿未来快照反推 |
| 给定历史片段的队伍说明 | 无独立的比赛范围关系 | 可在该比赛范围内采用 FaZe；这是用户素材提供的已知信息，不是自动推断 |

本轮普通请求中有 16 条可解析输出经唯一别名规范化恢复了标准 `sh1ro` 拼写。它们来自重复的少量音频区间，不是 16 个独立语音样本；只能说明后处理对已识别别名有效，不能修复听成其他词或完全遗漏的 ID。

生产词库应将选手实体、别名与战队关系分开，关系包含来源、快照时间、真实可核实的有效区间和比赛范围。**快照日期不等于转会日期，不能直接填成 valid_from**；缺失的历史区间必须保持未知。日期未知时结合多名选手与直接队名保留多候选，不能靠选手 ID 唯一推出当前队伍；替补/租借也是关系状态，不改变选手身份。

原型的历史日期 `2025-12-01` 仅为约束测试，未声称是实际比赛日期。未联网补全全部历史阵容，未将当前快照擅自改成新的确定事实。

## 4. 一个已落地的词库改善

本轮原 clip 的 25～30 秒输出将 `just a scout for Shiro` 译成带“侦察兵”的句子，金标和既有词库中的 SSG 08/Scout 译法均为“鸟狙”。

基础词包版本更新为 **0.1.1**，为 SSG 08 增加已有纠正机制可消费的条件规则：原文必须命中 `just a scout`，中文命中“侦察兵”；排除 scout ahead、scout for talent/candidates，通用 profile 不执行。

该规则在本轮原始输出中命中 4 条（同一片段在 2 个容量、2 次重复下），只替换已知误译词，不改写其他含义、不追加推理。它说明扩充经过验证的规则能够改善当前译文，而不是证明只更新阵容就能改善模型整体识别。原输出的其他名称、数字或句法错误仍然存在。

9 项 Flutter 词库测试全部通过，包含真实失败句的修正、普通侦察语境、人才侦察排除和通用模式。转会/别名原型另有 5 项测试通过，约束未知日期、历史信息和比赛信息的使用范围；连同首轮切分约束共 12 项 Python 测试通过。

本机 Flutter 生成配置曾引用仓库旧的小写路径，测试启动因此触发依赖准备等待；已修正两个忽略版本控制的 package_config.json 到现路径，再以 `--no-pub` 离线完成测试。未升级依赖或变更产品代码。

## 5. 下一步决策

- 分段继续采用语音停顿优先与时长兜底；1～5 秒固定截断仅保留为服务时间诊断。
- context 先保持 768 基线，同时保留 1024 对照。是否改变默认，以真实质量收益能否覆盖手机新增延迟/内存成本决定。
- 词库先完善唯一别名、弱别名、地图条件、高频误译和带时效关系；标准 ID 与转会关系分别维护。
- 已知场景信息仍未稳定改善双语输出。提示模板专项和自动推断的弃权/恢复能力仍是上线关口。

原始日志在忽略目录 `evaluation/results/s0-20261013/context_roster/`，新增 50 次实测计入结果的推理，与首轮合计 148 次；开发模型 token usage 仍不可获得，未用本地模型请求数冒充开发消耗。
