# 第四轮：质量指标与可复现实验

## 第一阶段目标（工程目标，不是已达成结果）

| 指标 | 定义 | 初步目标 |
|---|---|---|
| 英文 WER | (替换+删除+插入)/人工确认的参考词数；所有漏段计删除 | 采访 ≤15%，解说 ≤25% |
| 实体准确率 | 对齐后的选手/战队/地图名称正确提及数 / 参考提及数；额外编造单列 | ≥90% |
| 双语覆盖 | 有可懂语音的标注时间中，得到完整 EN+ZH 的比例 | ≥95% |
| 中文可用率 | 人工复核语义单元中，主谓对象、动作、否定和关键数字正确且译完的比例 | ≥90% |
| 语言异常率 | 完整双语输出中，经复核确有未译英文/无关语种的窗口比例 | ≤2% |
| 稳态速度 | 完整回放所有推理耗时 / 音频时长（RTF） | ≤0.7；实时队列丢段 0 |
| 字幕延迟 | 人工标注语义单元结束→首次可用字幕，而非窗口起点 | 手机 P95 ≤6秒 |
| 可靠性 | 异常/超时/乱序；独立静音集的虚构字幕 | 均为0；短素材不能代替长稳测试 |
| 本地内存 | cgroup MemoryMax / MemorySwapMax | ≤4096 MiB / 0 |

这些阈值用于确定产品方向。现有 clip_trans.txt 未精校且无时间戳，其 WER 只能作为相对代理指标；其他素材尚无独立参考稿，不输出准确率。语言脚本和连续英文检查只是疑点筛选，不能代替语义评分。静音以独立标注为准，不能用模型的 [NONE] 自证。

## 实验控制

同一 LiteRT-LM 模型、CPU 4线程、5秒窗口、无重叠、贪心解码、无思考，单模型串行，cgroup限额。Linux与手机的SDK、后端、收音和分段起点仍可能不同，不能称完全等价。先保留当前模型默认和Android队列。

1. baseline：现有提示，采访和Mirage文件直送。
2. explicit：仅改任务提示，明确英文转写+完整简体中文；同音频同分段。
3. english：诊断用英文单任务，系统和任务提示均改为转写；不作为双语候选，也不恢复级联。
4. 统一 quality_audit.py 从 raw 重算协议通过率、疑似语言混杂、耗时、内存；所有失败保留。格式兼容候选与模型提示优化分开计数。

先不启用质量拦截：把坏字幕隐藏不等于提升翻译质量。候选要在各开发片段分别比较，不能用平均数掩盖退步。晋级需至少改善一项主要质量指标且其余不退步，RTF/P95回归超过10%需另行评估；最终由精校参考与保留集确认。

## 2026-09-12 本轮已执行结果

采访和Mirage各执行 baseline / explicit / english，共81个窗口。原始记录和统一审计在 evaluation/results/round4-*.jsonl、round4-audit.json。统一审计使用同一解析函数，不采用旧回放器自带的宽松成功计数。

| 配置 | 采访双语窗口 | 采访RTF | Mirage双语窗口 | MirageRTF |
|---|---:|---:|---:|---:|
| baseline | 12/14 | 1.080 | 13/13 | 0.668 |
| explicit | 14/14 | 0.804 | 13/13 | 0.525 |
| english（非双语候选） | 不适用 | 0.424 | 不适用 | 0.375 |

重要限制：第一轮首次推理12.912秒，受冷缓存/调度影响；后续轮次运行顺序不同，不能把RTF差额全部归因于提示优化。baseline采访剔除首次和短尾后P95=5.816秒，explicit=4.844秒；仍需交替重复确认。全部运行使用CPU，不预测手机GPU速度。

explicit让采访窗口8从中文原样复制英文变成正常中文，但窗口14（65~66秒短尾）从无语音声明变为“Okay, let's start.”；未听音核验，列为潜在虚构而非成功。不能凭14/14晋级。英文单任务仍出现Remedy players、Yusuke、Molotow等可疑词，人名与短语问题未因取消翻译而消失。

### 已落地的低风险变化

- 增加quality_audit：统一解析、疑似未译英文/外语脚本检查、P50/P95/RTF/峰值RSS、逐窗口疑点输出。检查只报疑点，不删字幕、不生成内容。
- 增加english和explicit实验开关，不更改默认Android提示和串行队列。
- 补充trade术语元数据：仅no trade available / trade kill / trade frag / refrag触发“交易→补枪”，排除skin(s)、trade offer(s)。在两份双语输出中各修正1处，保留原句否定；普通trade不替换。只是术语改善，未修复整句语义。
- 原有16个评测测试通过，另做了格式恢复、缺失中文、外语混杂和术语正反例烟测；未新增测试类。

### 决策

不把explicit替换为手机默认；不恢复级联、不打包。没有人工确认参考的采访/Mirage不填WER或中文准确率；不把同一个Gemma的英文单任务当标准答案。

clip.wav同配置完整回归（各24窗口，末尾不足1秒按当前串行回放规则不送模型）：baseline相对WER=28.2%，explicit=29.9%；有序词覆盖76.3%→74.4%，实体计数召回代理均9.5%。explicit在固定基准上退步，故拒绝晋级。这是针对未精校参考的相对判断，不是模型真实准确率。基线复现此前28.2%的结果。

名单实验只加datasets.json中clip的地图/队伍/选手上下文，不改任务提示。需特别留意：窗口1生成了Zont1x，而参考对应的是torzsi；全篇名称计数即使增加，也不能作为正确指认的证明。名词纠正最终要按语句/时间对齐计分，不能通过把所有近音词强制替换成名单里的名字来刷分。

名单实验最终相对WER=34.7%，有序词覆盖69.4%，双语窗口22/24（基线24/24），RTF=0.785（基线0.754）；名称计数代理升至19.0%，但存在上述错指认，不能算准确率提升。因此该名单提示方案同样不晋级；已有App上下文功能不删除，仅不推广本轮新提示。

本轮总计153个窗口、6次模型运行，全部正常结束，无记录的推理异常；记录的进程峰值RSS最大1955.3 MiB，VmSwap均0。未测实时队列、温控或手机延迟，不能把串行回放无异常当作长期稳定性证明。

后续优先：先取得独立转写并复核短参考区间，再对单词被窗口截断、录音链路、短片段虚构分别做实验；可尝试更少且按片段命中的上下文，但不以当前整张名单方案覆盖手机默认。现阶段确认可保留的是自动审计和窄范围术语修正，不宣称核心识别准确率已提升。
