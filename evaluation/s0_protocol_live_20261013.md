# S0 补充验证：提示协议、实时节奏与场景恢复

日期：2026-10-13。接续 [context 与转会词库](s0_context_roster_20261013.md)。仍处于开发验证，未改动应用的采集、推理或字幕 UI。Android 未连接，不能以本机结果代替手机验收。

## 提示协议

同一 E2B 模型、LiteRT-LM 0.17.0、CPU 4 线程、MTP、768 context、128 输出 token、memory cache。所有模型任务串行，在 6 GiB cgroup、禁用 swap 的条件下执行。

先用 3 个语音区间各重复 2 次比较模板，并补充零 PCM 静音。语音结果：

| 模板 | 双语协议通过 | 推理中位数 |
| --- | ---: | ---: |
| 基线无提示 | 6/6 | 3.287 秒 |
| 原布局加场景术语 | 0/6 | 2.715 秒 |
| 将双语契约明确放入任务 | 6/6 | 3.615 秒 |
| 紧凑 system＋任务契约 | 6/6 | 3.285 秒 |
| LLGuidance＋JSON schema | 0/6 | 7.180 秒 |

原布局失败时，原始 response 中确实没有英文，并非提取器遗漏。明确双语契约能改善语音输出结构；失败组更快不能作为性能改善。

候选要求语音完整双语、静音严格 `[NONE]`。前三个带新协议的候选均未同时满足，筛选结果 `selected=null`，没有事后放宽规则。JSON 方案产生格式错误/过多空白；静音请求还出现 `compute_mask() called after stop` 异常。这里只能判断**当前模型、MTP、运行时和配置组合未通过**，不能据此认定结构化解码普遍不可用；关闭 MTP 的对照尚未执行。

随后增加条件明确的紧凑模板，在预先固定的 8 个未用于模板筛选的时间窗口验证：原 clip 4 个、NiKo 采访 2 个、Falcons/FURIA Mirage 和 NAVI/FaZe Nuke 各 1 个。它们仍来自已使用的素材，不是独立比赛保留集。场景由素材说明提供，是已知信息对照。

| 项目 | 无提示基线 | 新条件模板＋已知场景 |
| --- | ---: | ---: |
| 语音双语协议 | 8/8 | 8/8 |
| 推理中位数 | 3.126 秒 | 3.230 秒 |
| 静音协议 | 0/1 | 0/1 |

新增耗时约 3.3%，样本量不足以作稳态性能结论。静音输出分别为 `[NONE]` 附加中文行，以及双语两行 `[NONE]`，均按现有解析规则拒绝。没有为通过实验修改产品解析器。

**协议恢复还不等于准确性改善。** 新模板仍出现 Yesuke、Jacob、Zershian 等名称问题；Dust II 原文拼写更规范，但中文仍出现“尘土II”。未完成独立中文语义评分，不能宣称词库/场景已改善总体准确性。后续应将实体/术语定点收益与协议完整性分别验收，并使用同模板有无提示的对照，避免把模板变化的作用归给术语库。

## 按实际音频时钟输入

回放同一约 120 秒原 clip 两遍：固定 5 秒；累计 600 ms 非语音提前提交、5 秒兜底。每 20 ms 按墙钟释放 PCM，只使用已经完成的 32 ms VAD 帧，保留所有采集样本。一个在途推理、一个待处理槽；槽满保留最新片段并记录被替换的完整区间。末尾不足窗片段等待排队收尾，不替换较长待处理片段。

这里使用提前计算的因果 VAD 概率，**不计 VAD 与 Gemma 同时运行的资源竞争**。完整 PCM fixture 驻留约 3.84 MB；每段/队列副本上限 160 KB，未验证原生采集环形缓冲。该回放也没有应用当前 500 ms 重叠及不足 1 秒尾段过滤，是分段调度对照，不是 Android 行为完全复刻。计时终点为解码完成，未测字幕屏幕首显。

完整结果汇总至忽略目录 `evaluation/results/s0-20261013/protocol_live/summary.json`。汇总程序已核对所有切点与因果分段结果一致、交付区间完整覆盖音频，并检验解码没有提前使用尚未到达的片段。

| 指标 | 固定 5 秒 | 停顿 600 ms＋5 秒兜底 |
| --- | ---: | ---: |
| 提交/完成次数 | 25/25 | 26/26 |
| 丢弃音频 | 0 | 0 |
| 双语协议通过 | 21/25 | 24/26 |
| 完整金标英文 WER（包含解析遗漏） | 32.43% | 29.24% |
| 推理耗时 P50 / P95 | 2.814 / 4.058 秒 | 2.818 / 3.827 秒 |
| 切点至解码完成 P50 / P95 | 2.816 / 4.081 秒 | 2.821 / 3.828 秒 |
| 排队等待 P50 / P95 / 最大 | 0 / 0 / 0 秒 | 0 / 0.001 / 1.406 秒 |
| 峰值 RSS | 2.160 GiB | 2.237 GiB |

耗时分位数排除尾段，样本量分别 24、25；协议和 WER 保留所有尾段。采集 tick 最大迟到分别 89、15 ms。两个策略顺序运行，仍可能有机器负载偏差；没有超载/温控降速实验，不能据此宣称生产队列在所有情况下都不会丢句，待处理年龄上限也尚未在手机冻结。

停顿策略提前提交 5 次；VAD 最后语音帧至解码完成为 2.632～3.340 秒。以相同音频位置找到固定窗对照，其中 4 对都返回有效双语：提前返回 1.953～3.984 秒，中位数约 **2.059 秒**；第 5 次提前提交返回无效输出，不计入有效收益。这里是**调度代理指标**，未做词级音频对齐或逐句含义完整性判定，不能当作中文字幕首显延迟。连续讲话仍触发 5 秒兜底，切点之后约 2.8 秒返回也不意味着整句从开口起只延迟 2.8 秒。

曾有一次回放因实验日志的分段原因与解析原因同名而中止，修正字段后从头重跑；以上数据只来自完整重跑，不混入失败记录。

## 场景恢复与覆盖

[场景状态原型](s0_scene_state.py)保留多地图候选，对跨图普通词降权；需要独立点位证据或直接地图表述。重复段 ID 不累加证据，提示中已提供的实体不自证，历史表述不确认为当前地图；证据 60 秒过期，重置后旧会话不能恢复状态。

合成输入先错误支持 Nuke，再遇到 Mirage：第一次冲突返回未知，第二次直接 Mirage 表述恢复 Mirage。不同点位跨片段可以支持 Nuke。相关约束通过单元测试，但它们只验证状态逻辑，**不证明真实音频上纠错成功或场景推断准确**。

用已有模型原文连续输入：原 clip 的 21 条可解析结果、历史 Nuke 的 9 条可解析结果，均未达到确认条件。弃权减少了误推断风险，也暴露出实际证据覆盖不足。不能把“没有误报”当成自动场景能力通过，不能据此直接默认启用自动地图/战队绑定。本轮未验证自动战队推断，也未补全历史阵容。

## 本轮决策

- 保留 768＋紧凑提示候选；优先解决静音/无效输出和术语净收益，再决定进入生产。
- 分段继续采用停顿优先与 5 秒兜底；是否默认启用仍需手机上的服务时间、覆盖、VAD 开销和显示延迟证据。
- 场景确认继续允许未知；改善点位别名和位置表达识别后，用独立场次验证覆盖与误判，不能只降低阈值。
- 词库身份/别名、转会时效关系、条件纠正分层保持原计划；不能靠当前阵容唯一推定历史录像队伍。
- S0 尚未全部通过。手机未连接，真实切图/回顾旧比赛的连续标注、中文语义评分和长稳温控仍缺失；UI 仍处于计划阶段。

21 项 S0 Python 测试通过，Python 编译检查、shell 语法与差异空白检查通过。本轮完整结果包含 102 次模型请求（33 次筛选、18 次验证、51 次实际节奏回放），另有 3 次 warmup；中止回放不计入完整结果。原始音频、完整模型输出和逐段计时保留在忽略结果目录。本地模型推理次数不是开发模型 token usage，当前开发消耗仍未知。
